# Карта закладів

Vue 3 + Vite + Leaflet. Кафе, ресторани, бари, паби й фастфуд чотирьох міст —
Київ, Львів, Харків, Дніпро. Бекенда немає: усі дані лежать статичними файлами
в `public/places/`.

    npm install
    npm run dev

## Дані про місця

Місця запитуються тайлами фіксованого зуму (`z14`, ~1.5 км) — не сирим bbox,
інакше кожен зсув карти давав би унікальний ключ і кеш не спрацював би ніколи.

Ланцюжок джерел у `src/lib/placesRepo.js` короткий:

    памʼять -> бандл міста

Бандл — це один JSON на місто (`public/places/places-kyiv.json`). Він
завантажується раз за сесію, розкладається по тайлах у памʼяті, і далі рух карти
в межах міста не робить жодного запиту.

`public/places/index.json` — манифест: bbox кожного бандла, кількість місць і
`version` (хеш вмісту). Версія йде в URL як `?v=`, тому оновлення даних одного
міста не інвалідує кеш решти.

Плитка, яку не покриває жоден бандл, віддає `null` — це «за межами покриття»,
і карта просто нічого там не малює. Живих запитів у зовнішні API немає.

### Запис одного закладу

```json
{
  "id": "osm:n302631891",
  "name": "Чорноморка",
  "kind": "restaurant",
  "lat": 50.4664422,
  "lng": 30.5093152,
  "address": "Ярославська вулиця 5/2-А",
  "addressFrom": "building",
  "cuisine": ["seafood"],
  "wheelchair": "no"
}
```

`id` — тип і номер обʼєкта в OSM (`n` — node, `w` — way). Він стабільний назавжди
і водночас є ключем до деталей на вимогу:
`api.openstreetmap.org/api/0.6/node/302631891.json` — близько 800 байт, CORS
дозволений.
Тому телефон, сайт, соцмережі та інші рідкісні теги в бандл не кладуться:
дешевше взяти їх на тап, ніж возити в кожній сесії.

`address` є у 88% закладів, але власні теги має лише третина. Решту зшито з
довколишніх обʼєктів, і `addressFrom` каже, звідки саме:

| Значення | Скільки | Звідки |
|---|---|---|
| поля немає | 28% | власні теги закладу |
| `building` | 45% | будинок, у якому стоїть заклад |
| `near` | 15% | адресний обʼєкт у радіусі 25 м |
| адреси немає взагалі | 12% | не знайшлось нічого |

Неповна адреса — вулиця без номера — теж вважається за відсутню й дозшивається.

`cuisine` — масив, бо тег багатозначний. Значення нормалізовані (нижній регістр,
пробіли в підкреслення), але **не згруповані**: у чотирьох містах їх 121, з них
сотня трапляється один-два рази. Групувати доведеться окремою мапою.

`wheelchair` — `yes` / `limited` / `no`, є у 11% закладів. У фільтрі бере участь
тільки `yes` (239 закладів на чотири міста).

## Збірка бандлів

Джерело — локальний екстракт OpenStreetMap. Overpass для цього не годиться:
публічні мірори віддають випадкові 500-ки, і кожен прогін давав інший результат.

Одноразова підготовка:

    brew install osmium-tool
    mkdir -p data && curl -L -o data/ukraine-latest.osm.pbf \
      https://download.geofabrik.de/europe/ukraine-latest.osm.pbf

Далі:

    npm run fetch:places            # усі міста
    npm run fetch:places -- lviv    # одне місто

Скрипт робить три речі:

1. **Заклади.** `osmium tags-filter` за `amenity=cafe,restaurant,bar,pub,fast_food`,
   експорт у GeoJSON, розкладка по містах за bbox.
2. **Адреси.** Для кожного міста вирізає bbox з України, фільтрує обʼєкти з
   `addr:housenumber` і будує сітку 0.002° (~200 м). Заклад без вулиці шукає
   будинок, у якому стоїть (точка в полігоні), а якщо стоїть поза контуром —
   найближчий адресний обʼєкт у межах `ADDR_RADIUS_M`.
3. **Запис** бандлів і манифесту з хешем вмісту.

Проміжні файли лежать у `data/` (не комітяться, ~1 ГБ) і переюзуються, якщо
новіші за джерело. Повний прогін чотирьох міст — близько 40 секунд, з них 33
це вирізання bbox з України.

Міста задані в `CITIES` у `scripts/fetch-places.js`. Додати нове — один рядок
з bbox; дані вже локально, качати нічого не треба.

## Карта

Підкладка — CARTO Voyager, не `tile.openstreetmap.org`: політика OSM забороняє
продакшн-трафік, а головне — растр OSM малює власні іконки закладів, і ми
поверх них ставили б свої.

Маркери — кольорові кола 30px з іконкою Font Awesome, кольори типів у
`main.scss` (`--kind-*`). Нижче зуму 16 точки збиваються в кластери сіткою 68px.

`.map-canvas` має `z-index: var(--z-map)` не для краси: без числового z-index
елемент не створює контексту накладання, і внутрішні шари Leaflet (маркери
мають 600, маркер під ховером 10000) перекривають увесь інтерфейс.

## Замінити джерело даних

Контракт джерела — `loadManifest()` і `tilesOf(key) -> Map<tileKey, places> | null`.
Коли замість JSON-бандлів зʼявиться БД, достатньо реалізувати те саме проти свого
ендпоінта (Map з одним тайлом — валідна відповідь) і підмінити імпорт у
`placesRepo.js`. Композабл, карта і кеш не змінюються.
